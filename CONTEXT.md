# CONTEXT.md — domain glossary

Complement to `AGENTS.md`. Terms named during architecture design; empty terms are intentional omissions, not gaps.

> **Status**: the terms below split in two. *Implemented* (2026-09-18 architecture review): `Deployment`, `optconf`, `manage_policy_ops`, `doc_compose` — live in code. *Decided but not yet implemented*: `ApiExecutor` (A), `ExportResult`/`answer` (B), `ApiLocation` (C), `open_with_retry` (D). Until A lands, `ApiExecutor` below means the *new* operation-context seam, and the name collides with the *existing* `mcp_openapi/execute.py:ApiExecutor` (a `request(method, host, path, …)` Protocol) that it is planned to replace — see the `ApiExecutor` entry.

**Deployment** _(implemented)_ — the frozen value object + the single assembly entry. `common/deployment.py` holds all `HUAWEICLOUD_MCP_*` env-name constants (one definition each), the `Deployment` value (cross-mode knobs: mock triple, policy file, audit file, plus the env map for mode-specific lookups) and `resolve_deployment(args, env)` (getattr-safe). `huaweicloud_open_mcp/deployment.py` holds `build_app(modes, args, *, env, log_level, elicit_mode, …services)` — the only external assembly seam (single-mode and composite share one path); shared PolicyStore/AuditSink are constructed once and constructor-injected (ADR-0002). Per-mode `build_X_config`/`build_X_app` are internal seams (`dep=None` original signature kept for config-parse tests).

**optconf** _(implemented)_ — `common/optconf.py`: the optional-config loading discipline as one module. `load_opt_file(arg, parse, off, default_name)` is the sole three-branch idiom (None→default via `config_path`, missing→silent off / "off"+empty case-insensitive→off value / explicit path→`resolve_config_arg` fail-fast); `is_off` is the single off-sentinel predicate (adopted by spill, fixing its case-sensitive drift). The four file-resource loaders (hints / metadata_corrections / entity_index / deprecated) are one-line delegations; enum-style parsers (elicit mode / parse_modes / deprecated_mode / auth-demote) keep their genuinely different semantics out of it — the families differ as wide as their behavior.

**manage_policy_ops** _(implemented)_ — `safety/policy_store.py`: the manage_policy tool envelope as a single implementation for both modes. Action normalization, list/add/remove dispatch, result envelope (`ok`/`action`/`scope`?/`reason`?/`policy`), logging, and the not-configured refusal (one `NOT_CONFIGURED_REASON`) live here; the openapi and discover `service.manage_policy` methods are one-line delegations keeping their audit/guard decorators and mode-specific docstrings. PolicyStore's own interface is untouched — the envelope is tool-facing semantics, not rule storage.

**doc_compose** _(implemented)_ — `apie/doc_compose.py`: `compose_doc(raw, *, product, api, auth_demote, corrections)`, the single conversion composition point (convert + correct, ADR-0001). The "a converted doc is already corrected" invariant is producer-side: `LiveFallback` applies it in-place *before* caching, and the offline convert `main()` delegates to the same core. `correct_doc_cow`/`correct_api_result` are deleted — a corrected cache doc makes the consumer-side COW a hypothetical seam. Service reads docs; the corrections config threads `ServiceConfig → load_api_doc → catalog.find_api_doc → LiveFallback` as a startup constant.

**ApiExecutor** _(new, planned)_ — the seam between `ToolService` and *how an operation reaches Huawei Cloud*. Two adapters: `RealApiExecutor` (SDK-HMAC-SHA256 signs + builds the request from the OpenAPI operation) and `MockApiExecutor` (derives the API Explorer mock URL from `product`/`api`/`region`, peeling `_status_code`/`_number`). `execute.py` calls it, then normalizes + wraps the envelope. Replaces the *existing* `execute.py:ApiExecutor` (`request(...)` Protocol) + `_execute_mock` split. When implemented: the lane decision (`mock | obs | real`) is computed **once** at the entry (today `is_obs` is evaluated 3× per execute), and the executor adapter owns the mode name for the audit log line (today the block is copy-pasted 3×) — the authorize-exactly-once ordering becomes part of the executor's interface instead of comment-borne knowledge.

**RequestRefusal** _(planned)_ — the typed exception a real executor raises for the two real-only refusals (missing required `{project_id}` path param, missing `doc["host"]`). `execute.py` catches it and returns `{ok: false, reason: ...}`. The mock executor never raises it.

**ExportResult** _(planned)_ — the single typed shape `parse_export` returns (`usage` + `trace` tool-calls), regardless of whether the opencode export parsed fully or had to be recovered from truncated raw JSON. Hides the regex recovery inside `trace.py`; `runner` never sees the old `__raw_usage__`/`__raw_tools__` sentinel keys.

**answer** _(planned)_ — the canonical assistant text for scoring; sourced *only* from the live `opencode run --format json` NDJSON stream (`parse_run_output`), never from the export. Export supplies usage + trace only.

**ApiLocation** _(planned)_ — a frozen value type `(doc, path, method, op)` naming "one operation inside a converted OpenAPI doc". Owns the operationId lookup (exact + case-insensitive) so `find_api_doc`, `LiveFallback`, `format_api_detail`, and the `ApiExecutor` all pass/receive one named value instead of a bare 4-tuple.

**open_with_retry** _(planned)_ — the single public transport seam in `common.http`: opens a URL with timeout/retry/backoff, catching `HTTPError`, returning `(status, headers, body_bytes)`. Both the real and mock `ApiExecutor` call it; the old `_retry`/`parse_body` stay private behind it. Replaces the per-caller `_do`-closure duplicates.

**is_obs** — the routing predicate (`src/mcp_openapi/execute_obs.py`) deciding whether an operation goes down the OBS execution lane (`product == "OBS"`, host starting with `obs.` as fallback). The OBS lane — `ObsSigner` (HMAC-SHA1, `signer/obs.py`), dict→XML body serialization with `x-xml-root` preserved through the conversion pipeline, virtual-hosted bucket addressing, auto `Content-MD5` on write bodies, empty-value subresource auto-fill (`?tagging` etc.), JSON/octet-stream body branching by op `consumes`, binary-response placeholder rendering, XML `<Error>` parsing, and the `ObsHttpClient` transport adapter — is entirely self-contained behind this predicate; the generic SDK-HMAC-SHA256 lane is untouched. `service.execute_api` dispatches on `is_obs(product, doc)`.

**ObsRequest** — the value type `execute_obs` builds from user params: `(bucket, object_key, query, headers, body: str|bytes|None, content_type)`, naming one OBS operation's parsed request before signing/sending. `bucket_name` (declared `in: query` by API Explorer metadata) moves to virtual-hosted addressing; `object_key` is the sole path parameter; `Authorization`/`Date` header params are dropped (regenerated by the signer); required empty-value subresources are auto-filled.
